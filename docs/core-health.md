# 健康档案、观察与区域提示

健康档案与观察存放在账号业务数据库，支持 SQLite 与 PostgreSQL。附加表为 `health_profiles`、`observations`，不修改既有 schema version；删除账号时通过外键同步删除个人档案和观察。出生年份、基础情况、家庭史是用户自报信息，家庭史不等于个人确诊遗传病。

档案首次版本为 0，保存后递增。客户端保存必须带上读取到的 `version`；并发旧版本返回 409。清空基础情况、家庭史和区域同意可直接保存空列表/false。区域的 code 与 label 由服务端重建；只接受行政区文字或 `grid:<floor(lat*10)>:<floor(lon*10)>` 粗格，后端不接收经纬度或街道地址。

观察来源明确为 `manual`、`health_connect`、`healthkit` 或 `bluetooth`。来源标签是导入方提供的记录来源，不构成硬件认证，也不声称已经连接传感器。相同账号、来源、来源记录 ID 和指标构成幂等键：相同内容跳过，不同内容返回 409，整批回滚。时间统一为带时区的 UTC；最多兼容 5 分钟设备时钟偏差，但查询排除尚未到达当前时间的读数。

`get_observations` 默认返回最近 30 天最新 200 条，可指定 `limit<=500`、`days<=365`、`ids`。ID 筛选同时受账号和时间窗约束；个人基线不随 ID 筛选改变。基线使用最近 30 天静息观察，按北京时间自然日先取日中位数，至少 3 个不同日期才显示 median/p10/p90。`sample_count` 为有效日期数，`reading_count` 为原始静息读数数；不足时统计量为 null。健康页面基线只描述历史分布；病程分析应单独选取发病前基线，避免生病期间的值影响比较。

区域提示只纳入当前自愿同意、同一粗区域的账号；撤回同意立即退出下一次统计。近 7 个北京时间自然日与之前 7 天按病程开始日期分窗，按不同账号去重。呼吸道和胃肠道分别需要两类显式症状，或明确的 `disease_category=infectious` 与 `infection_group` 自报分类；不从自由文本推断感染。每个症状组至少 5 个不同账号才发布，仅显示 `5–9`、`10–19`、`20+` 档位。两个窗口都达到 5 人时才显示趋势，当前人数达到前窗的 1.5 倍标记 increased，否则 stable；前窗不足为 unknown。

结果不返回参与者身份、其他账号记录或精确人数。区域记录受参与率、自报偏差和起始日期影响，不代表人口患病率，也不能确认流行、诊断或排除疾病。竞赛训练语料不参与这些统计或诊断。

## 应用内流程与接口

健康档案和设备页面调用已认证的 `/api/v1/health/profile`（GET/PUT）、`/health/observations`（GET）、`/health/observations/import`（POST）、`/health/region` 与 `/health/context`（GET）。每次最多导入500条，界面以200条为批次；设备先显示真实能力/权限状态，再预览并由本人确认导入。相同内容重试不重复增加。手动记录永远带 `manual` 来源，普通心率的未知测量状态不会当作静息。

病程增加 `disease_category`、`diagnosis_name`、`diagnosis_source`、`infection_group` 与可选本人 `observation_ids`；药品增加实际起止日期、`adherence`、`response` 和备注。旧记录默认未知，不会自动推断感染或遗传病。用药期间自报好转/加重与实际用药天数一并展示，不能仅凭先后认定药物疗效或不良反应。

进行中病程分析使用病程内最近24小时的测量；已结束病程详情使用最后一天的测量回顾。手动填写正常数值不能掩盖新低血氧/高体温读数。静息比较单独查询发病前30天的数据，不受最近列表500条的密度限制：同来源、同设备、至少三个不同日期，并排除已记录病程。普通心率即使更新，也保留可用的近期静息读数供比较。历史相似度依据显式症状集合，只有本次开始前已结束的个人记录才比较病程时长与当时用药。

`GET /episodes/{id}`、`GET /episodes/{id}/analysis` 返回最新上下文分析；概览与工作区刷新进行中病程，健康档案与测量保存后自动刷新。分析包含明确优先级的 `action_plan`、`duration_days`、`history_comparison`、`device_context`、`profile_context`、`medication_review` 与 `regional_context`。就医触发和异常核实优先于一般记录建议；地域与相似历史不能降低危险信号优先级。成人发热、呼吸道防护、家族史及设备读数的官方依据在详情中可展开查看。

本人导出格式升级为 `schema_version:2`，包含完整 `health_profile` 和全部 `observations`，不会只导出列表前500条。SQLite迁移至PostgreSQL时，新附加表也会在同一事务复制与核验；旧三表源库继续兼容。
